# 畑だより — 農園販売デモ v0.7

日々の畑の写真・動画と、野菜セットの受け渡しを試すための日本語プロトタイプです。すべて架空データで、実際の販売サービスではありません。

[公開デモを開く](https://farm-dayori-demo-20261104.mobility-commons.chatgpt.site)

公開デモはURLを知る誰でも閲覧できます。サイトの公開状態と、アプリ内の「生産者／承認済み／未承認」切替は別です。この切替は表示の実演であり、安全な認証・権限制御ではありません。

## 起動方法

`farm-demo.html` をダウンロードし、パソコンのブラウザで開いてください。利用にNode.js、サーバー、アカウント登録は不要です。スマートフォンのファイルプレビューで動かない場合は公開デモを利用してください。

- [一枚仕様書（PDF）](farm-specification.pdf)
- [仕様書の編集用HTML](specification.html)
- [デモのソース](farm-demo.html)

## 試し方

1. 画面上部の見本は、3枚のイラストが同じ枠で3秒ごとに切り替わります。
2. 生産者で「写真をまとめて選ぶ」から複数写真を一度に選び、「はい、載せる」で1投稿にまとめます。「いいえ、載せない」なら取消します。確認ボタンは左が「いいえ」、右が「はい」です。
3. 「セットの種類を追加」で名前・仮価格・数量を入力すると、セットの枠そのものが縦に増えます。各枠の値は独立しています。
4. 元のセットのお客さんAを「用意しました」にし、承認済みのお客さんAへ切り替えて「受け取りました」を押します。
5. 未承認へ切り替えると、投稿とセットは表示されなくなります。

新しく追加したセットにはお客さんを自動登録しません。元のセットの毎週のお約束も変更しません。

## 写真が切り替わらない場合

1投稿に複数写真があるときだけ自動スライドになります。別々に投稿した写真は自動結合しません。各投稿に写真の枚数を表示します。

端末の「動きを減らす」設定が有効なら初期状態で停止し、その理由をボタンに表示します。再生ボタンで開始できます。写真1枚と動画は自動再生しません。

v0.6の初期見本が静止画1枚だった不備は、v0.7で3枚の見本に修正しました。ただし、実際のiPhoneで報告された「アップロードした2枚が動かない」原因を完全に特定したわけではありません。Chromiumでは文章付きの2枚投稿が実時間で切り替わって戻ることを確認しています。実機iPhone／Safariは未検証です。

## デモの制限

- 認証・通知・決済・注文送信・永続保存・端末間共有・自動週次更新はありません。
- 写真・動画と操作状態は、そのブラウザの実行中のメモリだけに保持し、再読み込みで初期化します。アプリから写真をサーバーへ送信しません。
- 写真は1投稿10枚・合計50MBまで、各ファイル20MBまで。動画は別投稿です。
- 3秒間隔、固定4:3枠、価格・数量、追加フォームの項目などは試作品の仮設定です。
- 商品写真と日々の畑の投稿は別の概念です。このデモは畑の投稿操作を優先しています。
- 実際の個人情報・取引には使用しないでください。

## テスト

アプリ利用とは別に、テスト実行にはNode.js、npm、PlaywrightとChromiumが必要です。

```sh
npm install
npx playwright install chromium
npm test
```

Linuxでブラウザのシステム依存が不足する場合は、Playwrightの案内に従って依存を用意してください。既存のChromiumを使う場合は実行ファイルを指定できます。

```sh
CHROMIUM_PATH=/usr/bin/chromium npm test
```

`test.cjs` は投稿・取消・動画・入力・受け渡し・スライド操作など14項目、`test-v07.cjs` は初期見本と文章付き2枚投稿の実時間切替、独立したセット枠、状態の紐づけ、動き軽減設定など5項目を確認します。実行結果JSONと確認用画像はローカルに生成され、Gitの対象外です。

既知の検証限界：実機カメラ、Safari/iOS、Firefoxは未確認。管理された検証環境ではfile://の直接起動が制限されたため、HTMLをブラウザに直接読み込む方法でテストしています。

## Go Bear to Farm!（追加部分）

2026年11月8日に Claude Code で追加した操作デモです。上の畑だより v0.7（Codex 実装）とは別のファイルで、`farm-demo.html` は変更していません。制作ツールと時期の内訳は [PROVENANCE.md](PROVENANCE.md) を参照してください。

- [デモのソース（go-bear.html）](go-bear.html)：パソコンのブラウザで直接開けます。外部通信・保存はありません。
- すべて架空データです。自動マッチング・予約・配車・外部送信はしません。

### できること

1. **関係図**：援農グループと、生産者グループ内の個々の農園を線で結び、「活動実績あり（実線）」「初回を相談中（破線）」「紹介あり・未訪問（点線）」をラベルと線種で示します。線を選ぶと、関係する農園・活動内容・直近の交流・次に相談したいことを表示します。線がないことは「受け入れ不可」を意味しません。
2. **農園の受け入れ（活動日ごと）**：生産者と参加グループが、それぞれ相談・延期・見送りなどを選べます。
3. **相乗りの需給**：「活動日 × 駅・バス停 × 農園 × 出発時間帯 × 往路／復路」の区間ごとに、乗りたい人数と提供できる席数（運転者と既存の同乗者を除く空席）を横棒と数値で比べます。区間どうしで不足と余裕を相殺せず、同じ人・同じ車の重複申告は先の区間だけで数えます。人数と席数が同じでも「成立」とは扱わず、移動の合意は一人ずつ記録します。

関係図で線や農園を選ぶと、その農園の区間に絞り込まれます。活動日を切り替えると、関係図・受け入れ・需給が連動します。

### テスト

`npm test` で既存のテストに続けて `test-gobear.cjs`（15項目）を実行します。数値の算出、相殺しないこと、重複を数えないこと、往路と復路の分離、絞り込み、まだ合意していない区間の表示、受け入れ合意と移動合意の分離、スマートフォン幅、外部通信がないことを確認します。
